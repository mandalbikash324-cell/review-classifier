Product Requirements Document

Multimodal E-Commerce Review Classification

Optimizing Sentiment Analysis Using Vision-Language APIs
Document version1.0
Target platformWeb demo (Streamlit or Gradio) with API backend
Project typeFinal-year academic project

1. Executive Summary

Traditional sentiment analysis relies solely on text, which can fail in e-commerce settings where physical product context matters. A review stating “The screen is huge” may be positive for a television but negative for a smartphone. Text alone also cannot verify a reported physical defect or determine whether an uploaded image supports the review.

This project proposes a multimodal classification system that uses a vision-language API, such as OpenAI GPT-4o Vision or Gemini 1.5 Pro, to analyze customer review text and an optional product image together. The system classifies sentiment as GOOD, NEUTRAL, or BAD, detects visible defects, and assesses whether the image aligns with the text claims.

3. Target Use Cases

  • Sentiment classification: Classify a review as GOOD, NEUTRAL, or BAD using the combined context of its text and product photo.
  • Defect and claim verification: Assess whether an uploaded image visibly supports a complaint, such as a claim that an item is broken.
  • Visual-text mismatch detection: Flag a review whose image appears unrelated to the text, such as a positive shoe review accompanied by an unrelated product image.

6. Pipeline Workflow

  1. Ingestion: The user enters review text and optionally uploads a product image.
  2. Formatting: The backend validates input limits, sanitizes text, resizes the image, and encodes it for the selected API.
  3. Inference request: The backend submits the prompt and available modalities with instructions for structured output.
  4. Vision-language processing: The model analyzes sentiment, visible defects, and image-text consistency, cross-referencing claims such as “shattered” with visible evidence.
  5. Output parsing: The backend validates the response fields and allowed sentiment values, handling invalid responses safely.
  6. Display: The UI presents the sentiment, defect and mismatch flags, and concise reasoning.

7. Academic Evaluation and Benchmarking

  • Ablation study: Compare text-only classification, image-only analysis where labels permit, and multimodal text-plus-image classification.
  • Confusion matrices: Compare class-level errors and examine whether multimodal evidence helps distinguish NEUTRAL from BAD compared with the text-only baseline.
  • Cost-benefit analysis: Document financial and computational trade-offs between API-based multimodal inference and a local CNN-plus-LSTM approach.

Evaluation results depend on the dataset, model, prompt, and provider. The accuracy, latency, and cost targets are project objectives to be measured, not assumed outcomes.
